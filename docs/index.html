asset-inventory

One command to inventory your OpenCode setup — every plugin, skill, command, MCP server, agent, and host capability, each with provenance.

一条命令，盘清你的 OpenCode 环境——每个插件、Skill、命令、MCP、Agent 与外层应用能力，都带来源追溯。

1 つのコマンドで OpenCode 環境を棚卸し — プラグイン、スキル、コマンド、MCP サーバー、エージェント、ホスト機能を、出所つきで。

명령 하나로 OpenCode 환경을 점검 — 모든 플러그인, 스킬, 명령, MCP 서버, 에이전트, 호스트 기능을 출처와 함께.

Одна команда — и всё ваше окружение OpenCode учтено: плагины, навыки, команды, MCP-серверы, агенты и возможности хоста, с указанием происхождения.

أمر واحد لجرد إعداد OpenCode الخاص بك — كل إضافة ومهارة وأمر وخادم MCP ووكيل وقدرة مضيفة، مع بيان المصدر.

Un solo comando para inventariar tu entorno de OpenCode: cada plugin, skill, comando, servidor MCP, agente y capacidad del host, con su procedencia.

Core idea: inventory what the machine can actually invoke, not which files exist on disk. Every row answers three questions — what it is, who brought it in, how to use it; the source must name the specific bringer, never a vague "some plugin".

主体思想：盘点的不是磁盘上有哪些文件，而是这台机器真正能调用什么。每行回答三个问题——是什么、谁带来的、怎么用；来源必须具体到带来者，绝不写"某个插件"。

基本方針：ディスク上のファイルではなく、この環境が実際に呼び出せるものを棚卸しします。各行は何か・誰が持ち込んだか・どう使うかの 3 問に答えます。出所は必ず具体的な提供元を名指しし、「とあるプラグイン」とは書きません。

핵심 사상: 디스크에 있는 파일이 아니라 이 환경이 실제로 호출할 수 있는 것을 점검합니다. 각 행은 무엇인지 · 누가 가져왔는지 · 어떻게 쓰는지 세 가지에 답하며, 출처는 반드시 구체적인 제공자를 밝힙니다.

Главная идея: учитывается не то, какие файлы лежат на диске, а то, что машина реально может вызвать. Каждая строка отвечает на три вопроса — что это, кто это принёс, как этим пользоваться; источник всегда называет конкретного поставщика.

الفكرة الجوهرية: الجرد لما يمكن للجهاز استدعاؤه فعلاً، لا لما يوجد على القرص. كل سطر يجيب عن ثلاثة أسئلة — ما هو، ومن جاء به، وكيف يُستخدم؛ ويجب أن يسمّي المصدر الجهة المحددة.

Idea central: se inventaría lo que la máquina puede invocar de verdad, no los archivos que hay en disco. Cada fila responde a tres preguntas: qué es, quién lo trajo y cómo se usa; la fuente nombra siempre al proveedor concreto.

Aspectos destacados

  • Provenance: built into OpenCode, brought by a plugin, created by you, or injected by a host app
  • Five-state labels: ✅available / ❌disabled / 📦shelf-only / 🚫absent / 🛑broken
  • Read-only and masked: changes no config; masks keys, paths, and private project names by default
  • Host-aware: binary-scans the app bundle for injected commands that plain grep misses
  • Diff mode: paste the previous JSON and get only additions and removals
  • 来源可追溯：OpenCode 自带、插件带来、你自建，还是外层应用注入
  • 五态标注：✅可用 / ❌已禁用 / 📦仅货架未装 / 🚫不存在 / 🛑已损坏
  • 只读脱敏：不改任何配置，默认打码密钥、路径与私有项目名
  • 外层应用感知：二进制扫描应用包，抓出普通 grep 漏掉的注入命令
  • 差异模式：贴上次 JSON，只输出增删
  • 出所が追える：OpenCode 組み込み・プラグイン提供・自作・ホスト注入
  • 5 状態ラベル：✅利用可 / ❌無効 / 📦未導入 / 🚫存在しない / 🛑利用不可
  • 読み取り専用・マスク：設定を変えず、鍵・パス・私有プロジェクト名を既定で伏せます
  • ホスト対応：アプリのバンドルをバイナリ走査し、grep では拾えない注入コマンドを検出
  • 差分モード：前回の JSON を貼ると追加・削除だけを出力
  • 출처 추적: OpenCode 내장, 플러그인 제공, 직접 작성, 호스트 주입
  • 5가지 상태: ✅사용 가능 / ❌비활성 / 📦미설치 / 🚫없음 / 🛑사용 불가
  • 읽기 전용·마스킹: 설정을 바꾸지 않고 키·경로·비공개 프로젝트명을 가립니다
  • 호스트 인식: 앱 번들을 바이너리 스캔해 일반 grep이 놓치는 주입 명령을 찾습니다
  • Diff 모드: 이전 JSON을 붙이면 추가·삭제만 출력
  • Прослеживаемость: встроено в OpenCode, принесено плагином, создано вами или внедрено хостом
  • Пять состояний: ✅доступно / ❌отключено / 📦только на полке / 🚫отсутствует / 🛑недоступно
  • Только чтение и маскирование: не меняет конфиг; скрывает ключи, пути и приватные имена
  • Учёт хоста: бинарный скан бандла приложения находит внедрённые команды, которые пропускает grep
  • Режим diff: вставьте прошлый JSON и получите только добавления и удаления
  • تتبّع المصدر: مدمج في OpenCode، أو من إضافة، أو من إنشائك، أو محقون من التطبيق المضيف
  • خمس حالات: ✅متاح / ❌معطّل / 📦غير مثبّت / 🚫غير موجود / 🛑غير متاح
  • قراءة فقط وإخفاء: لا يغيّر أي إعداد، ويخفي المفاتيح والمسارات والأسماء الخاصة
  • واعٍ بالمضيف: يفحص حزمة التطبيق ثنائيًا ليجد الأوامر المحقونة التي يفوتها grep
  • وضع المقارنة: الصق JSON السابق لتحصل على الإضافات والحذف فقط
  • Procedencia: integrado en OpenCode, aportado por un plugin, creado por ti o inyectado por el host
  • Cinco estados: ✅disponible / ❌deshabilitado / 📦solo en estante / 🚫ausente / 🛑no disponible
  • Solo lectura y enmascarado: no cambia la configuración; oculta claves, rutas y nombres privados
  • Consciente del host: escanea el binario del paquete y halla comandos inyectados que grep no ve
  • Modo diff: pega el JSON anterior y obtén solo altas y bajas
